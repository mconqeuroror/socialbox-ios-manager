# SocialBox 0.1.35 — installed device candidate

The rootless candidate is installed on the iPhone 8 (iOS 16.7.16, palera1n). Startup recovery succeeds after upgrade and a second daemon restart. The two existing Reddit containers, their code/home inodes, saved profile bytes and active license are preserved. All seven installed executable components match the final package. Traffic remains CLOSED.

This is ready for further controlled acceptance, **not approved for Facebook online/account use**. Facebook remains inactive in the production registry, and its `defaults-wire` result remains false. The phone has no proven managed per-app VPN assignment. A source import, stable offline launch or successful canary read does not establish full isolation.

The [machine-readable record](release-evidence/storage-lifecycle-0.1.35.json) lists all **127 passing test entrypoints**, the pasteboard check, per-unit commits, package/signature verification, sanitized device results and hashes of private evidence. Each implementation commit was checked from its exact staged snapshot and pushed to `feat/socialbox-multiapp`; no merge occurred. The full build uses Procursus ldid and the existing licensing public pin without an Apple team. This candidate was not published to APT.

Changes and reproduced failures:

- `a5ae3e2`: numeric/null-node address construction without DNS or service lookup. Facebook's local `0.0.0.0` address setup previously threw before any connection attempt. Connect/send/UDP and hostname lease checks remain enforced.
- `f3493f1`: preserve ElleKit's existing breakpoint dispatcher when Facebook installs its crash handler. The observed replacement caused a BRK/exception-port crash. Both set and swap operations are guarded; other exception masks are forwarded.
- `663ac55`: typed MobileGestalt defaults for unavailable controlled identities, with explicit absence verification. The native integer accessor previously aborted while QuartzCore rendered Facebook. WebKit now uses the actual underscore selectors and disables the underlying preferences; optional push registration installs only when present.
- `5ebca57`: retry a complete process snapshot after a process-exit race, at most three times. Persistent unreadable live processes still deny admission.
- `33c52f8`: durable root-owned storage receipts, global process closure, single-active admission, closed-home sync/removal and executable normalization in private IPA staging. Installer inspection receives temporary read access to exact code through group 33; mobile gets no additional access and the home remains closed. All-app startup/cleanup budgets include both registered families. The first upgrade exposed the old three-second budget; its failing-first regression and successful physical retry are retained.

The private offline helper used real clone creation, sync, export, deletion and storage authority. Only disposable Facebook profiles were admitted, using a private enabled descriptor, private ledger/operation paths, no reachable IP network, no network lease and no account login. Those fixture changes are excluded from the production package. The two fresh clones retain their own markers and deny sibling file contents through Foundation, POSIX and a direct ARM64 `openat` syscall in both directions. Final results are **76 PASS / 2 FAIL**: each clone can still stat the sibling home directory itself. Both remained running for at least 102/131 seconds after the startup repairs. A wakeups resource diagnostic occurred during offline retries; sustained background/energy acceptance remains outstanding.

Four disposable clones were removed through committed registry deletions. The original injection filter was restored byte-for-byte and temporary injection removed. An unsafe operation record created by the earlier failed test uninstall was **archived**, preserving its bytes, only after verifying the exact records/token, stopped helper/daemon, CLOSED lease, absent registrations/paths and committed deletion journals. This bounded recovery does not implement a general-purpose fence reset.

Next acceptance requires an actual MDM service and clone-to-VPN association, measured egress/failure behavior and Facebook SDK identity/wire observations. Apple's [deployment guidance](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment) requires a managed device for this iOS app-proxy arrangement. The [AppLayerVPN payload](https://developer.apple.com/documentation/devicemanagement/applayervpn) does not itself require iOS supervision. Enrollment and adoption of these ldid-signed clones without erasing this particular phone remain unverified; no erase or enrollment was performed. A local profile or UI label is not proof of enforcement.

Forty entries and 120 selections are covered by host storage tests. Forty physical clones, phone reboot, real accounts, authenticated cross-device restore, network outage/capture, rootful hardware and the requested screen recording remain NOT RUN. Screenshotr was unavailable. Directory metadata, opaque MobileGestalt keys, broker/shared surfaces and unresolved Facebook wire paths retain their ledger gaps. This is neither protection against root nor proof against server-side account correlation.

Older packages do not understand root-owned closed homes. Do not simply downgrade the daemon. Recovery must use exact receipt-bound inodes and recorded pre-upgrade ownership/modes after proven global termination; never recursively chown arbitrary application directories. Private pre-upgrade inventories are retained.
