# RedditBox phase 2 and phase 3 review

Original review: a9acd1968e12e519a3b6aac0843793732499a408. Phase 1 base: 06e5745.
Branch: fix/phase2-and-phase3. Reviewed code through acf256b.

**The requested phase-2 sequence is committed, with fourteen additional phase-3 fixes. This is not release approval or a claim that isolation is complete.** Proven clone-to-VPN assignment, verified browser login and safe in-app recovery from an unfinished operation fence remain open. Nothing has been pushed.

The commercial requirement that no outside observer can ever link profiles is not established. Clones share a kernel, physical hardware and a modified client. The control server intentionally knows device/profile ownership, and infrastructure operators can observe common ingress. User behavior, timing and opaque OS/client interfaces remain correlation channels after identifiers are separated.

## 4. Ranked residual risks and release gates

1. **Traffic escape, wrong managed mapping and provider authorization.** Highest impact: the real source IP or an unassigned path can link profiles immediately. Need a real signed provider accepted by the jailbreak, exact app-to-VPNUUID evidence and captures through startup/failure/disconnect. H08 remains an implementation gap.
2. **Client/OS access beyond hooks.** The app shares a process with the tweak and a kernel/hardware with every clone. Unknown MobileGestalt aliases, direct syscalls, opaque IOKit data, rendering/capability/timing and modified-client evidence remain available or unverified. Consistent synthetic fields do not defeat deliberate same-process inspection.
3. **Authentication and actual user flows.** Browser coverage and callback ownership remain unresolved. Keychain/App Attest policy can affect login/posting. Test login, browse, post and vote on every supported source/OS combination. Clipboard compatibility intentionally weakens isolation.
4. **Crash/timeout recovery and state transitions.** Delayed completions, rapid switching, provider/daemon restarts, low-storage writes and enumeration failure require fault tests. Persistent unsafe-operation recovery is a known missing flow, not merely hardware validation waiting to happen.
5. **Storage and destructive lifecycle.** Runtime keychain enforcement, SQLite/WAL restoration, installer data preservation, deletion retries and export cleanup need canaries/fault injection. App-file restore does not transfer device-bound credentials or prove retained login.
6. **Infrastructure and behavioral correlation.** Cloud ownership records, common proxy/control ingress, shared client/TLS traits and user timing remain signals. Local hooks cannot make those observers unable to associate profiles.
