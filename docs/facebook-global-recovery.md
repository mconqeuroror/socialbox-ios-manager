# Global recovery and maintenance — FBLIFE-004

This unit closes the remaining installation-recovery dispatch gap while keeping Facebook inactive. A global recovery pass validates the complete transaction inventory before replaying any app's work. An unknown/malformed owner, incomplete group identity or unfinished inactive-app transaction blocks the pass and retains every journal. Completed inactive backups remain retained. Each runnable owner is replayed through the existing exact-app recovery method, under one counted operation and one transaction lock. Exceptions and ordinary failure both release the lock and end counted work.

Startup migration and CLI provisioning now call this global entry point. Migration retains the existing pending-deletion rule: it must not replay an installation rollback that restores a profile being deleted. Other profiles may continue through the existing migration checks. Cloud snapshot quiescence and active cloud-profile retirement use the all-app coordinator after requesting CLOSED and before accepting firewall acknowledgement. A failed close still triggers a bounded stop attempt; it never becomes successful closure. Retiring an inactive target does not interrupt another active profile.

## Evidence

`tools/test_app_global_recovery.py` executes the shipped global dispatcher and registry migration with real temporary journals and a real file lock, using inert app service/ownership-reader providers. It passes 99 assertions with the production registry and 122 with an additive active-Facebook registry copied only into the temporary fixture. Cases cover mixed owners, invalid owner/group tuples, inactive pending work, failed handlers/retry, missing/inspection/canceled contexts, begin/lock failures, exception cleanup and suppression of recovery during pending deletion. The failing-first registry fixture showed migration previously provisioning after a Reddit-only recovery stub instead of rejecting an unknown foreign-app journal. The existing 724 actual per-app recovery assertions remain independent coverage of the underlying replay operations.

`tools/test_app_maintenance_closure.py` executes the actual cloud quiescence and registry retirement methods with real temporary lease files and synthetic gate/process/store providers. Its 45 assertions cover both global callers, ordering, every closure failure, cancellation/inspection, unrelated active profiles and conflicting cloud ownership. The failing-first fixture observed the previous Reddit-only controller selection.

The dormant `_enforceCurrentAssignment` / `_enforceCurrentAssignmentWithContext:` legacy methods in `RBXCloudSync.m` have no scheduled or direct caller in the daemon tree; this unit does not activate them or treat them as an implemented background proxy-revocation feature. Replacement still has its own remaining process/owner integration. Facebook backup-state semantics, runtime SDK compatibility and network/MDM acceptance remain pending.
