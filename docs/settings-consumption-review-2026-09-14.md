# Editable settings consumption review — 2026-09-14

This review started from `1a61bc1` and traces all visible launcher fields through persistence and active Reddit consumers. The integrated fixes and exact validation records are listed in [the preparation report](settings-review-preparation-2026-09-14.md) and [validation manifest](settings-review-validation-2026-09-14.json). Baseline failures below are identified explicitly; they are not claims that the fixed code still has those defects.

This is source and host-fixture evidence. It is not proof that every device API, request, SDK, restore path or managed VPN configuration is isolated. Facebook remains `runnable=false`: its shipping selector exposes source setup only. There is no Facebook clone acceptance, and no social login, posting or sharing was performed for this review.

## Identity editor: choices, persistence and active consumers

`launcher/RBXIdentityViewController.m` loads a private draft, submits choices to `previewIdentity`, and requires a matching checked draft before `applyIdentity`. `daemon/RBXContainerRegistry.m` builds and validates the candidate, reserves unique identifiers, writes the profile and ensures/synchronizes the clone. `RBXConsistencyValidator.m`, `RBXProfileIO.m` and the canonical catalog provide the server-side checks. Launch preparation durably freezes identity before the lease is armed or the app launches; a later launch failure does not remove that lock. The security-only path preserves the identity fields. A UI control or successful preview does not replace those checks.

- **Device model / product type:** a catalog picker sends `productType`. The registry selects the model and derives marketing name, board/hardware model, regulatory model, region model number, RAM, GPU and screen metrics. Canonical nested fields rebuild `mgOverrides`. Active consumers include `RBXMobileGestaltHooks`, `RBXDeviceHooks`, `RBXSysctlHooks`, `RBXSensorHooks` and the GPU hook. Reddit request identity also derives the device name, dimensions and generated User-Agent from these fields. Model changes must be tested against serial/UDID/IMEI format rules and the selected iOS support list; the text field itself is not arbitrary model input.
- **iOS version:** the catalog picker sends `iosVersion`; build and Darwin release are derived and validated. Active `UIDevice`, `NSProcessInfo`, sysctl/uname and Reddit request fields consume that tuple. The baseline `NSProcessInfo.operatingSystemVersion` required three components and called the physical original for `26.5`/`26.6`. The prepared fix accepts strict two or three numeric components, treats an omitted patch as zero and rejects malformed/overflowing input using the existing fallback. The actual hook body is tested, including the absence of original calls for valid two-component versions.
- **Country:** sends `country`; an assigned proxy's country must match. An unassigned profile stores the requested region in `proxy.country` and `validation.proxyCountry`. Locale, timezone, carrier, model region suffix and location must remain coherent with that country. A live proxy mismatch is a separate refusal, not an invitation to rewrite a used identity.
- **Language and region / locale:** sends `locale`; the registry validates country membership and derives `device.language`. Active `RBXLocaleHooks` consumes locale/language, telephony uses the region, and supported Reddit headers and body fields consume locale/language.
- **Timezone:** sends `timezone`; country membership and selected city timezone are checked. `RBXTimezoneHooks` and supported Reddit UTC-offset fields consume it. Actual network exit verification remains separate.
- **Carrier:** sends the selected MCC-MNC in `carrierCode`; the registry chooses a matching country catalog entry and persists name/MCC/MNC/ISO data. `RBXTelephonyHooks` consumes those fields. This represents a synthetic carrier, not a change of SIM or network route.
- **City:** sends `city`; registry requires a country catalog city with matching timezone. `RBXLocationHooks` consumes its derived coordinates. An unchanged region/timezone/city now retains the stored point during unrelated edits; the native matrix reproduced 318 unwanted movements before the fix. A changed city receives bounded jitter around its catalog point. Preview and apply construct a new-city point separately, so the city-only preview does not promise exact coordinates for a newly selected city. First-use freeze remains enforced.
- **Device name:** sends `deviceName` to `device.deviceName`, canonical MobileGestalt, `UIDevice.name` and supported hostname surfaces. Reddit Device-Name is separately derived as `Apple;<productType>`. Explicit blank, whitespace-only, oversized and non-string names now fail validation rather than silently retaining the previous value; valid 1–64-character names persist.
- **Battery offset:** sends `batteryOffsetPercent`, stored in `timing.batteryOffsetPercent`. `RBXBatteryHooks` offsets a synthetic per-container charging/discharging cycle and clamps it. Zero does not restore the physical battery level. The baseline accepted nonnumeric/fractional strings through `integerValue`. The integrated candidate rejects garbage, fractional and out-of-range values rather than coercing them to another integer, with native candidate regression coverage. `RBXIdentityHelp.h` now explains that zero keeps the synthetic cycle unchanged and does not report or affect real battery charge.
- **IDFA posture:** sends `idfaPosture` (`random` or `zeroWithATTDenied`). The candidate enforces a nonzero UUID for random, or zero IDFA for denied posture. `RBXAppleIdentifierHooks`, the `ATTrackingManager` hooks and supported Reddit advertising-ID fields consume this policy. It is a reported app-process posture, not a modification of the system's tracking permission database.
- **Visible serial number, UDID, IMEI, Wi-Fi MAC, Bluetooth MAC, platform UUID:** these fields now appear in Device identifiers even in the simple editor. Strings are trimmed and stored in `serials`; explicitly blank or malformed required manual inputs fail instead of keeping an unseen old value. Omitted legacy partial-request fields retain their existing semantics. The catalog/template, format, Luhn/TAC and MAC checks apply; supported generic model templates may omit IMEI. Wi-Fi and Bluetooth addresses must differ. Reservation history and other profiles guard against identifier reuse. Canonical MobileGestalt, IOKit and sysctl surfaces consume the applicable fields. This does not prove coverage of every private API returning an equivalent identifier.
- **Visible IDFA and IDFV:** UUID strings persist in `ids`; IDFA posture still controls the effective advertising ID. Denied ATT displays an all-zero, read-only IDFA before Check/Save. Returning to random posture restores editing and retains the displayed value; consistency validation rejects an invalid random IDFA. Active Apple identifier hooks and supported Reddit fields consume them. Native manual-input and actual UIKit fixtures cover these transitions; the UI cannot override the consistency validator.
- **Reddit installation ID and external installation ID:** persist in `reddit.installId` and `reddit.externalInstallationId`, with UUID and uniqueness checks. Active `RBXRedditAPIHooks` uses the installation ID in its known headers and recognized body keys, and the external ID in recognized body/SDK-related fields. It deliberately excludes known account, authorization, loid and session fields. These controls are absent from the Facebook editor construction and are not a Facebook identifier implementation.
- **Reddit font size (16/17/19):** persists in `reddit.fontSize`. `RBXRedditAPIHooks` substitutes recognized outgoing font-size keys, preserving numeric/string representation. This is not a general UIKit font-size hook or proof of changed visible Reddit text size. The field is not shown for Facebook.
- **Automatically fill / Set manually:** the visible mode selector changes presentation without generating or saving values. The explicit Fill automatically action obtains a fresh daemon proxy-region observation, selects a compatible catalog model/iOS and generates a complete private identity draft. The UI opens manual review and retains unsaved compatibility-policy changes. Check and Save always submit the exact displayed manual choices; they never regenerate on Save. The random candidate retains operator metadata, app ownership, proxy state and non-editor security policies. Existing model-picker regeneration still retains the selected compatible model/iOS. Used identities stay frozen; incomplete private drafts show missing identifiers and cannot save identity changes. Locked policy-only edits preserve their earlier validation path. See [the automatic identity preparation report](automatic-identity-preparation-2026-09-14.md) for proxy observation limits and acceptance steps.
- **Set from proxy:** requests `detectProxyRegion` and populates draft country/timezone/locale/carrier/city suggestions. It does not save the draft or assign a profile proxy by itself. The daemon must repeat applicable validation on apply and on protected launch.

The editable fingerprint has no independent screen, RAM, GPU, build, Darwin, installation timestamp, User-Agent, machine-ID, loid or session field. For pre-use Reddit model/iOS/scale changes, the registry now removes a stale optional User-Agent override so the existing runtime builder uses the new tuple and installed app metadata. Unchanged, unrelated, security-only and Facebook overrides retain prior behavior. The actual candidate and header builder pass 148 cases. Untouched imported opaque overrides still require a separate provenance review; this change does not certify every custom string.

## Eight compatibility/privacy toggles

The UI sends booleans in `choices.security`; the registry persists exact `enabled`/`blocked` strings. These settings are permitted through the security-only edit path after identity freeze. The normal apply lifecycle and readiness still apply. No toggle authorizes Facebook execution or disables the managed VPN admission requirement.

- **Allow App Attest → `security.appAttest`:** `RBXAppAttestHooks` blocks by default and permits the supported original App Attest API path when enabled. Signing/entitlement compatibility remains a separate requirement. This can expose real service behavior; it does not generate a synthetic server attestation.
- **Allow DeviceCheck → `security.deviceCheck`:** the same module gates supported DeviceCheck APIs. Default is blocked; profile override permits the original supported API behavior.
- **Allow loopback connections → `security.localNetworking`:** `RBXSocketGuard` permits supported loopback operations when policy and lease checks allow them. It does not generally allow LAN discovery, arbitrary private addresses or nearby-device networking. The updated label and help state this loopback scope.
- **Allow motion sensors → `security.sensorAccess`:** `RBXSensorHooks` gates supported motion readings. Enabled can expose real sensor measurements shared by physical hardware. Synthetic display metrics are a separate part of the module and are not switched back to real metrics by this toggle.
- **Allow network metadata → `security.networkMetadata`:** `RBXNetworkIdentityHooks` gates supported real network metadata API results. It does not select, test or replace a proxy route.
- **Allow third-party network SDKs → `security.thirdPartyNetwork`:** `RBXProxyHooks` relaxes its supported HTTP(S) request destination restriction beyond descriptor critical hosts. It is a request-host policy, not discovery/control of every SDK. Socket/proxy/lease checks still apply independently.
- **Enable strict timing virtualization → `security.strictTiming`:** `RBXRuntimeHooks` chooses synthetic timing behavior for supported runtime surfaces. Some synthetic identity/sysctl surfaces are independent, so this should not be presented as a universal real/synthetic clock switch.
- **Allow system clipboard → `security.systemClipboard`:** `RBXPasteboardHooks` permits supported access to the shared iOS clipboard when enabled; blocked mode suppresses supported clipboard operations. Enabled is explicitly cross-profile shared behavior. The tweak does not clear the user's system clipboard.

There is no visible legacy Keychain-remapper toggle. `RBXInstallKeychainHooks` remains dormant. The optional underlying `security.keychainSync` policy is not one of these eight UI switches. Broad legacy defaults hooks also must not be inferred active from their mere presence in source.

## Diagnostic controls

**Sentinel enabled, interval in minutes (1–1440), and optional clipboard challenge** send `configureIsolationSentinel`, separate from identity choices. The daemon validates settings, ownership/data availability and recovery fences, then persists `containers.<id>.isolationSentinel` in the central store. `RBXSentinelController` publishes bound control data; `tweak/LeakDetection/RBXIsolationSentinel.m` performs the supported in-clone probes. Enabling requires reopening the clone to install its probe thread. A clipboard challenge is an explicit optional operation, not an identity field.

The prior sentinel fix distinguishes absent, denied and unknown evidence. Missing cross-container markers are not comprehensive isolation proof; weak historical PASS records normalize to NOT_RUN while valid LEAK findings and durable alerts remain. Settings and summary screens must not convert NOT_RUN into “all passed.” This review does not repeat the prior runtime storage audit.

## Creation, organization and launcher defaults

- **New-container name:** the create alert/wizard submits `nickname`; registry/central-store and clone display metadata consume it. It is an organizational display name, not the spoofed device name.
- **New-container country / Auto:** submits `country` plus `autoRegion`. Blank means detect through the selected configured proxy; explicit country remains subject to daemon/catalog/proxy checks. It is not a direct edit of an already frozen identity.
- **New-container role:** one of default/signup/warmup/spam. It persists as profile metadata and has no hook or network-policy consumer.
- **Default country and default role in Settings:** app-scoped `NSUserDefaults` keys (`RBXDefaultCountry`, `RBXDefaultRole`, with the Facebook suffix for that descriptor). The reviewed baseline never consumed default country in creation and consumed default role only in the advanced alert. The prepared fix shares `RBXCreationDefaults` across normal/advanced creation and wizard initialization. Saved defaults fill new forms; existing draft values, including explicit empty Auto country, win. Absent country preserves Auto. Settings now displays that absence accurately, saves blank as Auto instead of silently US, normalizes valid two-letter text and rejects malformed text without changing the stored value. Daemon validation remains authoritative for country support.
- **Role and notes editor:** sends `updateMetadata`; the registry validates the role and up to 200 Unicode scalar values of notes. Metadata revision/dirty state supports cloud conflict handling. This does not change identifiers or grant launch authority. “Use cloud role & notes” is an explicit metadata-conflict operation.
- **Role filter and grouping:** list presentation only; grouping is app-scoped launcher preferences and filter state is local UI state. It must not filter the inventory supplied to MDM coverage checks.
- **Passcode / confirmation / remove passcode:** launcher-only Keychain gate, independent of clone identity/network admission. Replacement now updates atomically, adds only on not-found and retries an insertion race once, retaining the old verifier on failure. Only errSecItemNotFound means no gate; unavailable, denied and corrupt records remain protected and fail verification. Exact existing salt/digest format remains supported. Explicit removal shows an error if deletion fails. Native provider and action fixtures exercise these paths without reading any real Keychain item.

## Shared device settings and setup inputs

- **Proxy library name, HTTP proxy URL (including credentials), optional rotation URL, authorization header, authorization token and GET/POST method:** `RBXProxyEditor` sends the entry to `RBXProxyLibrary`. That layer validates/normalizes and saves through `RBXSecureConfig` in the device Keychain. The selected entry is shared across app workspaces. Selection/edit/deletion notifies the daemon via durable configuration actions. The protected launch still resolves the profile's assigned proxy, live country, exact lease and managed VPN state; the app selector does not create independent device network stacks.
- **Legacy/wizard proxy configuration fields:** the same proxy/rotation/header/token/method values go through `RBXSettingsViewController.validateAndSave` and `RBXSecureConfig`, then configurationChanged/testConfiguration. Rotation URLs require HTTPS and other constraints. HTTP proxy parsing is shared. Test-result freshness and current configuration binding must remain visible; simply saving an entry is not successful egress verification.
- **Access/license key:** `RBXSecureConfig` stores it privately. Activation sends server URL in durable IPC and retrieves the key through the private seam; no app profile identifier consumes it. The license screen normalizes and bounds a supplied key and requires deliberate activation/validation. Access remains device-wide.
- **License server origin:** license UI checks an HTTPS origin without path/credentials/query/fragment; the daemon/license guard owns trust, token and request validation. This setting does not change the app's own account server or any identity field.
- **Cloud server URL and pairing code:** Settings sends `configureCloud`; the daemon sets the server, pairs, syncs device configuration and then inventory. The visible URL check is not the final authority; `RBXCloudSync` validates the accepted server. Pairing/cloud sync can affect device proxy assignment and metadata, not the meaning of the eight profile compatibility toggles.
- **Reddit latest-known-version override and check interval:** stored in `com.redditbox.appversion.plist`; `appVersionConfigurationChanged` restarts `RBXAppVersionMonitor`. These are monitoring inputs, not synthetic OS/app-version fields. Numeric version validation remains; interval now requires an integer from 1–720. Failed writes preserve prior settings and the draft, report an error and send no reload action. Blank version removes only its override; unrelated settings remain. The 49-case native persistence fixture proves this boundary. Source archival still needs device acceptance: checkNow examines the visible original Reddit install, so absence of that install skips its version comparison.
- **Source IPA file selection:** the active Reddit setup and inactive Facebook source sheet stage an app-bound import. The daemon validates the source, publishes its private cache and closes an active device session as required. Import is not clone creation or hook readiness. Replacing a Facebook source remains an import operation; its placeholder has no identity/privacy settings or runnable container actions.
- **MDM/VPN share and Firewall Setup:** actions/exported configuration, not editable spoofing settings. Exact signed clone identity, management adoption and device evidence remain required. These actions must not be treated as a privacy toggle or satisfied by the proxy configuration alone.
- **Anonymous account-status username:** a transient input to the separate anonymous, read-only profile viewer. It is not saved as a profile identity field and not a Reddit/Facebook login, account token or posting control. This review did not run it.
