# Facebook acceptance runbook

Facebook clone acceptance is **NOT RUN**. The shipped descriptor remains inactive; importing a decrypted source is the only Facebook workflow currently exposed. This runbook defines the evidence needed to enable and accept a future candidate. It does not authorize changing readiness flags, removing MDM checks or opening a diagnostic network bypass.

The [binary audit](facebook-binary-audit.md) and [two original-app metadata captures](facebook-runtime-observations.md) are completed evidence for Facebook 578.1.0, build 1063022819. They are not clone acceptance. The source IPA SHA-256 is `2cdaab3bd8bd0238660ea23b566b7bd7713121d996032bbc045d4066d2233e8a`. The device check verified the phone upgrade from 0.1.13 to 0.1.16 and completed decrypted Facebook source import through a durable daemon receipt: **installation/source import PASS**, [device evidence](socialbox-phase23-device-evidence.json). The actual launcher/Files-picker flow was not visually exercised; source staging alone would not have established this pass.

## Current blockers, in order

1. **Storage and lifecycle boundary.** Three original Keychain groups and both generic-password/key-class items are observed. Distinct clone groups, Security wrappers, cleanup receipts and app-owned installation/deletion/replacement/backup code now have executable tests. Synthetic Keychain device probes passed, but live Facebook clone/state semantics are not yet verified as a whole. See the [boundary plan](facebook-keychain-boundary-plan.md). Keep Facebook inactive.
2. **Real MDM/network gate.** The current test phone has no configured MDM. Local installation and proxy health do not establish managed per-app routing. Supervision, managed adoption of the exact clone build and a matching provider/bundle mapping are prerequisites for gated clone traffic.
3. **Identity provenance.** Family/machine identity generation, persisted backups and server-issued identifiers are not traced end-to-end. Actual Facebook UA fields and install-timestamp sources are unverified. The compatibility `reddit` section in a Facebook draft does not cover Meta fields; see [profile scoping](facebook-profile-scoping.md). DeviceCheck/App Attest calls are observed, but default-blocked and per-profile-enabled Facebook compatibility are not established.
4. **Transport and background behavior.** MQTT/custom Meta transports, QUIC/UDP, callback routing and background/wake behavior require device evidence beyond the one observed NSURLSession host. Original background declarations do not prove that clone signing has neutralized every wake path.
5. **Full operator acceptance.** A/B identity stability, account login, browse, post/share, restart, restore, replacement and load acceptance have not been run on Facebook clones. Host tests and inactive UI fixtures cannot substitute for them.

## Recording and stop rules

For every step record `PASS`, `FAIL` or `NOT RUN`, package revision/version/SHA-256, source hash/version/build, device/iOS/jailbreak context, app type, private A/B container-to-bundle mapping, start/end time, and the receipt or capture establishing the result. Keep raw logs private; publish only redacted metadata. Never export tokens, passwords, account identifiers, Keychain contents, key material, full authenticated URLs or request bodies as routine evidence.

A pass requires the expected observation, not merely absence of a crash. Record a specific blocker for every unrun step. Do not copy older version numbers, example profile IDs or deployment commands from [device-acceptance-final.md](device-acceptance-final.md); inspect the actual artifact and installed tools. [on-device-smoke-checklist.md](on-device-smoke-checklist.md) provides the existing shared/Reddit procedures. Its Reddit-specific acceptance helper must not be invoked with Facebook IDs and presented as Facebook coverage.

Use disposable containers and operator-owned test accounts. Login, publishing and sharing are deliberate actions by the operator in the app; this runbook does not automate them. Choose the intended account, content, audience and destination in the app before confirming each post/share. External callback flows need the same deliberate review. A reused account is an explicit account-level link and cannot serve as proof of independent accounts.

On any unexplained entitlement, receipt, process-drain, restore or routing failure, preserve diagnostics and recovery state, close traffic using the supported application workflow, and stop dependent steps. Do not hand-edit journals, entitlements, activation flags, profiles or lease files to obtain a green result.

## Phase A: audit and supported preparation

1. **Install the candidate — shared.** Install the exact locally built package through the project's existing deployment procedure. Verify its actual installed version and daemon/launcher/provider health; capture package identity and relevant installation output. The recorded 0.1.16 phone upgrade passed, with installed daemon/tweak/launcher hashes matching the package, license active, network closed and no operation recovery. Existing container IDs and identity fields were preserved. Open the launcher, confirm the Reddit selector retains its current data and navigation, then select Facebook. Expected current UI: **Container support pending verification**. Facebook creation, Open, delete, replace, MDM and diagnostics controls must be absent. This visual portion remains untested on the phone; simulator fixtures are separate evidence.

2. **License — shared.** Use the existing license screen and authorized license. Confirm a valid license's normal status and that an invalid/expired test fixture prevents gated operations with a clear error. Preserve the real license privately and restore normal state after controlled testing. Facebook selection must not create a second license store or bypass the device-wide gate.

3. **Proxy — shared configuration, per-container selection later.** In the existing Proxies flow, use an authorized test proxy and its country/rotation configuration. Verify health and actual observed exit identity using the existing diagnostic workflow. Do not infer a particular proxy assignment from country alone. Failure, stale authorization or unavailable exit verification must leave app traffic closed. Record credentials only in the private configured store.

4. **Source import — Facebook-specific, available now.** Select Facebook, choose **Source setup**, then **Import Facebook IPA from Files** in the **Facebook source** modal. Select the audited decrypted IPA. Record the app-bound request/operation receipt and terminal outcome; verify the cache identifies `com.facebook.Facebook`, executable `Facebook`, expected version/build and the validator's Mach-O/decryption result. The expected descriptor-owned cache is `/var/mobile/Library/RedditBox/SourceFacebook/Facebook.app`.

   Import must close any active device session before serialized maintenance. A Files staging path is not the final cache and a submitted request is not completion. Restart the launcher after submission and confirm the same receipt resumes without duplicate import. Importing another approved decrypted Facebook IPA through this same action is the supported source-replacement workflow. Preserve a working cache if validation fails; wrong-app/encrypted input and interrupted/cancelled staging are negative cases, preferably first exercised with fixtures. Do not run destructive source tests against the only retained copy. **Done** closes the source modal. Facebook source hide/archive/removal is not currently offered.

5. **Evidence alignment — Facebook-specific.** Match the installed/source build to [static evidence](leak-surface/facebook-binary-evidence.json) and [selected runtime evidence](facebook-runtime-evidence.json). Original-app captures prove named callers/groups/statuses only. Re-audit a different source build before inheriting its allowlists. The reviewed daemon import reports Facebook private cache decrypted at 578.1.0/1063022819. Reddit remains decrypted at 2026.36.0/664762, and its source Info.plist/executable hashes are unchanged. Actual inactive Facebook creation was refused. See [device evidence](socialbox-phase23-device-evidence.json); this validates daemon source import, not the untested device Files-picker workflow or Facebook clone acceptance.

## Phase B: admission, clones and managed routing

All remaining Facebook execution steps are **NOT RUN and blocked by the current inactive descriptor**. The labels below describe the implemented active UI fixture as an operator guide for a future admitted build. Their existence in a fixture is not proof of a runnable lifecycle.

6. **Admission review — Facebook-specific with shared regression gates.** Complete the group/restore plan, app-specific identity audit and all failing-first tests before considering a new runnable candidate. Independently review the admission change. Re-run the existing Reddit regressions and record their result against that candidate. Ensure Facebook defaults/wire readiness has justified coverage for actual Meta persistence and transport callers; do not make it pass solely because generic hooks installed.

7. **Create A and B — Facebook-specific.** In the future Facebook **Containers** tab use `+`, **New container**, name/proxy/country, **Generate & review**, then **Review identity**. Create two disposable containers with different identity seeds and explicit proxy assignments. Review coherent model/iOS/locale/timezone/country, IDFA policy, stable IDFV and default blocked DeviceCheck/App Attest. Check that repeated review/retry preserves the candidate rather than generating a new identity silently.

   Record distinct exact bundles and all expected Keychain groups. Neither profile may inherit a Reddit source path, sibling group, original App Group or source bundle entitlement. Verify inside-out signatures, removal of unsupported extensions and complete bootstrap/marker ownership. Verify install timestamps are plausible and staggered **at the actual Facebook persistence/wire source**; generated compatibility timestamps alone do not meet this requirement. Keep traffic closed through installation and identity review.

8. **MDM adoption — shared enforcement, exact Facebook outputs.** On a supervised device enrolled in the operator's real MDM, use the future Facebook export flow and **Share MDM/VPN setup** action. Verify the exported clone IPA, `socialbox-facebook-per-app-vpn.mobileconfig` and `socialbox-facebook-mdm-app-mapping.json` refer to the exact A/B bundles and current signature. Follow the MDM vendor's established managed installation/adoption procedure; installing a mobileconfig locally does not prove managed app association.

   Confirm the existing provider `com.redditbox.firewall.PacketTunnel`, payload identity and app mappings agree. Original `com.facebook.Facebook` is deny-only, and launcher/daemon/provider infrastructure is not treated as a target clone. A missing association, replaced signature or stale signing contract must require re-adoption and deny Open. Verify on the device, not only by reading exported JSON. No MDM on the current phone means this step remains blocked.

9. **First Open and isolation canaries — shared sequence, Facebook-specific observations.** Use **Open Facebook** for A only after managed routing is proven. Capture CLOSED → armed → open evidence with matching profile, generation, boot and live process identity. Run a reviewed Facebook-capable synthetic probe for every derived group/class and private sandbox/defaults boundary; current Reddit-only probes are insufficient. Seed only known synthetic values. Verify source/sibling group denial, reference isolation and the exact full entitlement set before using accounts.

   Observe first relevant SDK accesses after bootstrap readiness; validate family/vendor backup handling and default blocked DeviceCheck/App Attest. Gather actual UA consistency and local/server identifier provenance with an explicitly scoped evidence method. Header names alone cannot prove UA values, and a successful service read cannot identify its contents. Preserve server-issued/authentication identifiers unless an audited policy establishes why they must change.

10. **A → B → A and cross-app switching — shared global sequence.** Capture each supported switch, including Reddit → Facebook and Facebook → Reddit. The previous session must close and drain, all registered target-family processes stop, and only then may the next rotation/identity/launch occur. Verify a fresh receipt for the next generation and one global active lease. B must not read A's canaries; returning to A must preserve A's synthetic identity and allowed state. Audit source and extension process scope without killing unrelated infrastructure. A process-scoping unit test is not a device drain result.

## Phase C: behavior, failure and persistence

11. **Login, browse, post and share — Facebook-specific, operator-driven.** The operator logs into A with an owned test account, browses feed/profile/media and confirms the displayed account privately. Repeat in B with a different owned test account. Record success/failure and capture intervals, without publishing account names. A login wall or integrity challenge is a compatibility result, not a pass.

   For each container the operator deliberately creates one agreed test post and performs one agreed share in the intended private/test audience or destination. Verify completion in the app and record the result. Do not infer post/share success from an HTTP request. Returning A → B → A must retain the intended separate sessions without exposing the other account. Any callback/SSO transition must return to the intended clone under an audited URL-scheme policy; original shared schemes are unresolved until tested. Cleanup of test content is the operator's deliberate in-app action.

12. **Attestation policy — Facebook-specific.** Exercise default blocked behavior first. On a separate disposable profile, test the existing explicit per-profile enable setting only after the operator chooses it. Verify the signed entitlement, hook behavior and actual completion/compatibility outcome agree. Record unsupported/challenged results honestly. App Attest keys and service state must remain scoped to the intended identity; neither copied key IDs nor random replacement UUIDs prove a valid enabled mode.

13. **Egress and fail-closed — shared guard, Facebook transports.** During browse/media and idle periods collect privacy-preserving transport evidence for HTTP, persistent sockets/MQTT, DNS, IPv4/IPv6 and UDP/QUIC paths actually used. Correlate observed exit/route with A then B; static destination roots are an allowlist basis, not proof of critical traffic. Test proxy loss, denied/missing MDM binding, expired/stale lease and process restart using supported controls or a reviewed fixture. Traffic must not fall back to a direct route.

   Check both directions of established connections: after closure the old session must neither send additional traffic nor deliver new inbound data. Include buffered and long-lived transfers rather than only new HTTP requests. Observe any WebKit, custom transport or out-of-process auth path separately. An NSURLSession hook count does not cover Tigon/Proxygen/MQTT; unobserved paths stay marked unverified.

14. **Background, lock and wake — shared closure, Facebook-specific declarations.** Test foreground → background → foreground, screen lock/unlock and idle periods while capturing process and lease state. The original declares `bluetooth-peripheral`, `external-accessory`, `fetch`, `processing`, `remote-notification`, `voip` and `audio`. Inspect the final Info.plist and effective signature to state which capabilities remain; extension removal and denied push entitlements do not by themselves prove all background behavior is removed.

   Exercise only operator-authorized test stimuli. Do not place calls or send messages to other people to create a wake. If a required mode cannot be stimulated safely, mark it NOT RUN. Verify an inactive container cannot wake into another container's session, retain an old persistent connection or bypass a closed gate. Any future background override needs an explicit profile policy and its own acceptance cases.

15. **Restart and interrupted-operation recovery — shared transaction safety, app-aware ownership.** Restart launcher, daemon and then the phone through supported procedures. Verify source receipt, selected app, A/B identities and completed operations survive; traffic must await fresh readiness after process/boot changes. With disposable candidates, interrupt creation/install and source replacement at reviewed failure-injection boundaries. Resume through the supported UI and verify the same identity/journal is recovered. Preserve snapshots and pending operations when recovery cannot prove its target. Do not manually delete recovery files to continue.

16. **Backup, import and restore — Facebook-specific contract pending.** Source IPA import is distinct from profile backup import. The app-bound backup implementation still rejects the inactive Facebook descriptor; record that refusal as the expected current boundary. [Host transaction evidence](facebook-backup-integration.md) is complete for the current unit. Device acceptance must test same-logical-identity restore, reinstall of the same bundle, cross-device restore and restoration as a deliberately new identity separately. Verify owner/source/group-policy validation occurs before writes, quiescence before snapshot, and exact candidate cleanup on failure.

   App-data inclusion does not transfer Keychain/device-bound keys or guarantee login. Check restored family/vendor-ID defaults and attestation references against the defined identity policy before opening traffic. Preserve or regenerate identity only according to that explicit operation; a fresh local container ID alone does not define it. Record required re-login and actual results instead of claiming seamless account restoration.

17. **Delete B — Facebook-specific full group proof.** Keep A as a survivor and use only a disposable B. Seed synthetic items in every B group/class, then use **Delete**. Require complete authorized cleanup receipts for all expected groups and classes before uninstall/profile removal. Verify B's items are absent, A's remain readable and original/foreign groups were untouched. Test locked-device or injected helper failure: deletion must remain incomplete/resumable and preserve recovery state. Unlock/retry must finish without broadening the cleanup target.

18. **Replace — Facebook-specific new identity with shared closure/rotation.** With a disposable profile, use **Replace with new**; after a controlled interruption use **Resume Replace**. Verify a durable new container/identity with fresh owned groups and successful required rotation before retiring the old profile. Resume must reuse its recorded candidate, not allocate more identities. Complete old-group cleanup before committing removal. A new source version that updates the same logical container is a separate operation and must preserve its declared identity policy and trigger MDM re-adoption when required.

19. **Regression and scale — shared plus Facebook-specific results.** Repeat the critical Reddit checks on the final candidate, including its existing identities, source, signing, MDM association, switch and deletion behavior. Only after the A/B path passes, exercise the requested 30–50-container resource/management workload with disposable profiles and approved infrastructure. Do not automate creation of social accounts. Record storage, process, launcher responsiveness and operation/recovery results; two successful containers do not establish scale acceptance.

## Release evidence

The release record must link the package/source hashes, tests, real MDM adoption, A/B canary results, manual critical-path outcomes, egress/background captures and recovery/delete/replace/restore receipts. Keep unresolved rows open in the leak-surface inventory. A complete source import, a clean build or an original-app launch cannot close clone isolation rows. Meta family findings are reused for the Instagram phase later; they do not admit Instagram execution.
