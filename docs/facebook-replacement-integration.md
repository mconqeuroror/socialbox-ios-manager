# App-bound replacement — FBLIFE-005

Facebook remains inactive. Replacement now binds the original and candidate to the same registered app, without changing Reddit format-1 identity fields or the existing replacement phase order. Facebook format 2 includes its source identity and the complete independently derived old/new clone targets. Their bundles and Keychain groups must be distinct. The original keeps its data until candidate creation, rotation and validation have succeeded and the deleting phase is durable.

The backend selects the original app's process controller for inactivity inspection and the global coordinator for closure. Candidate creation passes the app type to the existing registry path. Retries validate an existing candidate before provisioning, authorization, proxy work or metadata updates. A profile without installed metadata can be considered only during failed-create recovery; a completed candidate must have its complete installed bundle/group identity. The profile is checked again after rotation.

Every published checkpoint validates the complete journal. It cannot replace a prior app/candidate identity or overlap another replacement. The same checks run inside the central-store update to catch state changes since preflight. Original deletion requires the matching live profile or canonical ownership from its durable deletion journal. The registry's new read-only identity accessor validates the journal and returns only the independently derived app/group tuple, not retained profile bytes or artifact paths. Missing or conflicting ownership blocks deletion.

## Executable evidence

- The existing actual transition engine now runs 21 failure/retry scenarios for each app. Its shared 43 ownership cases remain green. Another 26 identity cases prove the unchanged Reddit shape, distinct Facebook group sets and rejection of incomplete/unknown owners.
- `tools/test_app_replacement_backend.py` executes the actual backend and transition engine against real temporary JSON journal storage and inert registry/process/cloud/proxy services: 250 assertions. Failures at each service and checkpoint preserve the original until successful deletion, and retry creates exactly one candidate of the selected app. Foreign candidates are rejected before provisioning or authorization, foreign original profiles cannot be deleted and stored candidate identities cannot be substituted.
- `tools/test_app_deletion_flow.py` now has 341 assertions, including the actual durable deletion identity accessor. Missing journals supply no ownership proof; unsafe identifiers are rejected; completed receipts expose canonical ownership without private evidence.
- Failing-first fixtures reproduced Facebook's old format rejection and the backend's Reddit-only process selection. Complete static/native build and package inspection are recorded with this unit.

These tests use synthetic services and future Facebook profiles while the production descriptor remains inactive. They do not prove live Facebook startup, account compatibility, a real proxy exit change or managed VPN routing. Facebook restored-state semantics and runtime/MDM/network acceptance remain required before activation. Replacement intentionally retains the existing requirement for a verified new exit; this unit does not treat a static unchanged proxy as successful rotation.
