# Facebook Keychain boundary: implementation prerequisite

This plan tracks the remaining coordinated integration. The policy core and Security wrappers are now implemented with failing-first tests in `FBKEY-001` and `FBKEY-002`; they are not yet a complete live clone boundary. Facebook remains inactive and its app-specific defaults/wire readiness remains failed. Signing/runtime and the production cleanup helper now use the complete group contract with synthetic device evidence. Lifecycle journals and actual Facebook app acceptance remain before activation. New tests expand coverage before each affected Reddit path changes.

Latest integration: [launch/gate](facebook-launch-integration.md), [global recovery](facebook-global-recovery.md), [replacement](facebook-replacement-integration.md) and [backup reconstruction](facebook-backup-integration.md). These code paths now carry app ownership and executable failure tests. Historical prerequisites below describe the original gaps; live Facebook SDK/state and MDM/network acceptance still prevent activation.

## Implemented first unit

[RBXAppKeychainPolicy.h](../shared/RBXAppKeychainPolicy.h) derives three distinct ordered groups: the existing Facebook primary, primary plus `.family`, and primary plus `.app`. The canonical registry maps the three observed source names to these groups. Version 1 metadata requires the complete ordered set. Reddit retains its singleton group and empty additional metadata. The native golden/policy fixture has 39 assertions.

The alternative installer in [RBXKeychainHooks.xm](../tweak/Container/RBXKeychainHooks.xm) covers `SecItemAdd`, `SecItemCopyMatching`, `SecItemUpdate`, `SecItemDelete`, `SecKeyCreateRandomKey`, `SecKeyCreateWithData`, and `SecKeyGeneratePair`. [Current IPA import evidence](facebook-keychain-api-evidence.json) justifies all three key-creation families. The installer composes optional local-only sync policy once, requires a validated profile and exact group metadata, and leaves the dormant legacy namespace hooks untouched. It preserves returned Security objects and actual access-group names; no captured evidence currently justifies fabricating reverse-translated attribute results. Facebook caller compatibility must still be verified.

Tests execute the shipped wrappers (200 assertions), the actual installer in six fresh processes (16 assertions), and the existing Reddit sync fixtures. Invalid or unvalidated Facebook profiles install no hooks; Reddit defaults install none, Reddit local-only installs four, Facebook policy installs seven once. The entire pre-existing build/native test list, cloud app registry/authenticated scope and TypeScript checks pass.

The [synthetic device probe](../tools/device_app_keychain_probe.m) then passed **237 checks** on iPhone10,4 / iOS 16.7.16. Each mobile-uid process had exactly its own three derived groups and no App Groups/platform entitlement. Both stored/read distinct genp, inet, certificate and key items, resolved own persistent references, denied foreign groups and foreign persistent references, and searched only their own groups with an omitted-group query. Clearing B left A readable; final cleanup verified both fixtures empty. [The redacted evidence](facebook-keychain-device-evidence.json) binds every result to helper/policy and private-receipt hashes. Identical signed executables were killed when launched from mobile Caches but executed from root-owned `/var/jb/tmp`. The initial killed run provided no evidence; the later completed run did. This proves the tested Security boundary only, not sandbox enforcement, live Facebook interception/SDK ordering, account compatibility, MDM or network acceptance. The remaining integration below is still in progress.

## Implemented signing and runtime integration

`FBKEY-004` connects the complete group policy to main executable signing, effective signature inspection, provisional/committed profile metadata, marker format 2, bootstrap comparison and runtime admission. Facebook profile IO rejects incomplete group metadata. Startup validates its exact team and ordered group set and completes an own-canary round trip including cleanup in every group. A cleanup failure now denies readiness. Reddit keeps its singleton signature, format-1 marker and profile field shape.

The full shipped rewrite/validator tests exposed another pre-existing Facebook blocker: bootstrap comparison always required a `reddit` dictionary. It now requires the selected app identity and compares that app's optional namespace, with the original required Reddit dictionary retained for Reddit. Actual full-method fixtures pass 189 checks with Facebook inactive and 213 with a test-only active descriptor; runtime entitlement/probe fixtures pass 57, group/marker policy 47, and bootstrap/runtime policy 176. Those fixtures use inert signer/service providers and do not enable the production descriptor. The full pre-existing host/native list passes. The production multi-group cleaner is now implemented and tested as described below. Journal recovery is the next coordinated unit; Facebook remains inactive until the remaining app-specific and device gates are complete.

## Implemented installation and rollback integration

`FBLIFE-001` adds an exact per-app installation record. Reddit retains format 2 and its prior identity fields. Facebook format 3 binds app/source/container/bundle/primary/full groups and rejects missing metadata or untyped recovery flags before even prepared-state cleanup. The installer accepts only a private record owned by its manager. Per-app recovery stops its own processes, preserves original and failed-install snapshots, restores a previous install in place and rejects foreign app/transaction/marker metadata. A mixed recovery scan leaves a validated other-app journal for its own manager; unknown owners block recovery. Removal capture validates the selected source or clone and its sandbox metadata, and the uninstall entry guard cannot accept another app owner.

Failing-first actual recovery tests found acceptance of unknown owners and malformed Facebook state flags. The new fixtures pass 724 recovery/filesystem assertions and 103 removal identity assertions; installer evidence also exercises Facebook and missing group fields. The [complete intermediate rootless build](facebook-install-recovery-build-0.1.22.json) passed 97 host/native entrypoints. It was inspected but not installed or published. These fixtures do not substitute for an actual Facebook install/rollback or global caller integration. The remaining work is global multi-app maintenance, deletion and replacement journals, backup state semantics, and live app/network/MDM acceptance.

The [runtime observations](facebook-runtime-observations.md) establish successful original-app queries to `T84QZS65DQ.platformFamily`, `group.com.facebook.family`, and `group.com.facebook.Facebook`. They include both generic-password and key-class items. `group.com.facebook.family.securefamilydeviceid` is an observed **service in the family group**, not another access group. No captured value establishes identifier provenance or wire semantics. The [original entitlements](facebook-binary-audit.md) also declare App Groups; those can expand Keychain access and must not be copied into clones.

Runtime explicit group requests use the new app-specific wrappers when admitted.
- [RBXCloneManager.m](../daemon/RBXCloneManager.m) signs and verifies the complete main-bundle group set. Facebook marker/bootstrap/profile metadata binds that set; Reddit scalar metadata stays unchanged. Nested objects retain empty entitlements and source extensions are removed. Installation recovery and deletion now bind the same full app/group tuple.
- [RBXContainerManager.xm](../tweak/Container/RBXContainerManager.xm) verifies effective team/groups and a canary round trip in every group before readiness. The separate synthetic device test covers key objects and persistent references; live Facebook calls and early hook ordering remain to be tested.
- [RBXKeychainHooks.xm](../tweak/Container/RBXKeychainHooks.xm) keeps legacy item-attribute namespacing dormant. The common installer selects the seven-function group policy for a validated Facebook bootstrap, or the unchanged optional four-function Reddit sync policy. No item service/account/tag material is rewritten.
- [RBXKeychainCleaner.m](../daemon/RBXKeychainCleaner.m) derives one or three exact groups from the registered clone bundle. One signed helper carries the exact full set and canonical primary application identifier; this matches the tested clone signature and avoids an implicit primary group expanding a secondary-only helper. It proves each group after irreversible privilege drop, clears genp/inet/cert/keys, and rechecks all groups after all mutations. Reddit retains its single-group format-1 receipt; Facebook format 2 carries app/policy/full groups and individual group proofs. The daemon signs that exact set and requires a matching complete receipt before reporting cleanup success. Deletion journal admission now verifies that same complete tuple.
- [RBXContainerRegistry.m](../daemon/RBXContainerRegistry.m) retains deletion phases `prepared`, `keychain-cleared`, `uninstalled`, `cleanup-complete`, `committed`. Reddit format 1 remains unchanged; Facebook format 2 carries an explicit app/source and complete group set. Installation recovery validates legacy Reddit format 2 and group-bound Facebook format 3 through `RBXAppLifecycle.h`. Global maintenance callers and replacement still need their coordinated update.

## Proposed boundary, subject to tests and device evidence

The policy is a deterministic, one-to-one mapping from each explicitly registered source group to a different group owned by the same clone. The canonical primary remains first and represents platformFamily/default creation. The family and Facebook groups use the `.family` and `.app` suffixes. Those names and the versioned metadata must now be carried consistently through signing and lifecycle operations before publication.

The immutable tuple is app type, container identity, exact bundle, group-policy version and complete ordered group list. It must be derivable independently rather than accepted from untrusted profile strings. No source group, sibling clone group or foreign app group may appear in the effective entitlement set. Keep source App Group entitlements absent. A changed source version that requests an unregistered group remains denied and cannot silently expand the policy.

Known source-group inputs map to their corresponding clone groups. Exact groups already belonging to that clone are idempotent. Unknown or foreign explicit groups cannot be promoted to an entitled group or retried using a broader query. Service, account, label, application tag, item data, device keys and server/session material keep their semantics.

**An omitted group is not an alias for every operation.** Preserve the system's omitted-group behavior and ordering: creation uses the default permitted group, while searches may span permitted groups. Do not force all omitted-group lookups to the primary or introduce a fallback search across source groups. Malformed group types and unsupported queries require a defined fail-closed error contract without suppressing Security's validation. Native tests must establish the exact statuses and result shapes before relying on this behavior.

## Coordinated code seams

1. **Canonical policy and profile transport.** Add any group data to [app-registry.json](../cloud/src/config/app-registry.json), regenerate [RBXAppRegistryData.h](../shared/RBXAppRegistryData.h) with [generate_app_registry.py](../tools/generate_app_registry.py), and expose derivation/validation through `RBXAppRegistry.h`. Extend [RBXProfileIO.m](../daemon/RBXProfileIO.m), [RBXProfileTransport.h](../shared/RBXProfileTransport.h) and any affected [RBXDataSchema.h](../shared/RBXDataSchema.h) preflight with typed, versioned metadata. Preserve absent `appType` and scalar-group Reddit documents byte-for-byte where currently promised. Bind clone markers, bootstrap and source-policy version to the same tuple; do not accept caller-supplied arbitrary groups.

2. **All relevant Security entry points.** Implement an explicit Facebook-only policy path rather than activating the legacy namespace installer. Cover query dictionaries in `SecItemAdd`, `SecItemCopyMatching`, `SecItemUpdate` and `SecItemDelete`, and update attributes separately. Specify output behavior for returned attribute dictionaries containing access groups, arrays and combined data/attributes/reference requests. A reversible translation back to source names, if required, must be justified and tested; exposing a mixture of mapped and unmapped names can change application branching.

   Cover `SecKeyCreateRandomKey` top-level and nested `kSecPrivateKeyAttrs`/`kSecPublicKeyAttrs`, plus `SecKeyGeneratePair` or other creation paths if the audit identifies them. Handle permanent versus ephemeral keys and missing/nested groups without rewriting key material. Exercise SecItem additions through `kSecValueRef`, certificate/identity/key references, `kSecMatchItemList`, and `kSecValuePersistentRef`. Reference-only queries can omit item class. Preserve opaque references and ownership rules; never serialize or manufacture replacement persistent-reference bytes. Prove that a reference originating in a sibling/source group cannot bypass authorization. The observed `keys` lookup does not establish Secure Enclave origin or the needed creation caller.

3. **Hook ordering and readiness.** Compose group mapping with the existing optional synchronizable policy once, in a tested order, without double-hook recursion. [RBXAppRuntime.h](../shared/RBXAppRuntime.h) must continue to gate the exact descriptor/bootstrap before installing the Facebook path. `RBXContainerManager.xm` must reject missing, duplicate, extra and foreign effective groups and must verify each required group. Integrate with [RBXHookReadiness.h](../shared/RBXHookReadiness.h), [RBXLaunchSafety.h](../shared/RBXLaunchSafety.h) and [RBXNetworkGate.m](../daemon/RBXNetworkGate.m) without relaxing profile/generation/PID/boot binding. Demonstrate interception before the first relevant SDK access. Group checks alone cannot make Facebook defaults/wire readiness pass.

4. **Signing, source changes and MDM adoption.** Update all single-group comparisons and marker checks in `RBXCloneManager.m`, including clone validation, deletion preparation and recovery. Keep `application-identifier`, team and Keychain list independently validated; they are not interchangeable fields. Main and nested signed objects must have only their intended entitlements. Extend the conservative signing-contract fingerprint in [build-version.py](../scripts/build-version.py) and its tests if a new signing policy/helper becomes an input. A changed effective signature requires the existing MDM re-adoption path. Source import/replacement must neither rewrite the original archive nor silently migrate previously signed clones to a new group set.

5. **Deletion and cleanup proof.** Implemented as `FBKEY-005`: one minimally entitled helper carrying the exact complete compiled group set, with the canonical primary as its application identifier. It never accepts a caller-supplied access group. The [physical-device evidence](facebook-keychain-cleanup-device-evidence.json) records the actual production helper clearing synthetic B, independent confirmation that all B items were already absent, and all A data still readable. All 237 accompanying probe assertions passed; both fixtures and remote test executables were removed. Native tests inject failure at each group, retry partial cleanup, recreate an earlier-group item during the final group, and forge/miss receipt fields. All 95 host/native entrypoints and static checks pass. This does not yet prove the installation/deletion journal path or live Facebook behavior.

   Each required group must prove authorization, delete and verify all four stored classes, including local/synchronizable selector coverage, before the journal can advance to `keychain-cleared`. Identity items require consistent certificate/key handling; they must not survive through an untested reference path. Bind each receipt to app, bundle, policy, target group and operation nonce. Aggregate only the complete expected set. Partial success, locked-device errors, killed helpers, stale receipts or missing groups leave a resumable incomplete deletion; no uninstall or profile removal follows. Retry must tolerate already-cleared groups while protecting the surviving container. Preserve private job ownership, bounded output, irreversible privilege drop and helper-exit fencing.

6. **Recovery and replacement.** Extend installation/deletion journals with validated ownership and group-policy state before accepting Facebook. [RBXReplacement.m](../daemon/RBXReplacement.m) currently stores format-1 old/new IDs and creates a candidate through the legacy Reddit creation wrapper; its backend also uses default process controllers. The replacement journal must preserve the selected app, candidate identity and exact group policy through every resume. Do not regenerate another candidate after a failed install. Old-container deletion can commit only after the replacement is valid and every old group is proven cleared. Coordinate these paths with the global process/traffic closure implementation; changing the group helper alone does not fix lifecycle ownership.

7. **Backup and restore.** [RBXBackupSnapshot.m](../daemon/RBXBackupSnapshot.m) snapshots app files under a quiescence contract; it does not snapshot Keychain state. [RBXCloudSync.m](../daemon/RBXCloudSync.m) explicitly rejects non-Reddit backup owners and declares Keychain `not-exported`, device-bound keys `not-transferable`, and login preservation false. Its restore worker uses Reddit identity/source paths. [RBXBackupArchive.h](../daemon/RBXBackupArchive.h) validates archive paths, not identifier provenance.

   Define separately same-logical-identity restore to a fresh local container, reinstall into the same bundle, cross-device restore, and replacement with a new identity. A new local container ID is not automatically a new logical identity in the current restore contract. Audit restored defaults/plists for family/vendor-ID backups and attestation references before opening traffic. Do not copy device keys or claim an account session survived because app files restored. Failed restore must retain the original snapshot and explicit recovery state; cleanup may touch only the failed candidate's proven groups. Keep Facebook import rejected until the complete contract is implemented and tested.

## Implemented deletion integration

`FBLIFE-002` binds the retained deletion target, journal, manager and artifact identity to one registered app. A parsed profile owner must agree with the independently stored owner. An unparseable profile may use an independent stored owner; without one it is retained, not guessed to be Reddit. Both retries and final profile removal recheck ownership. Exact previously retained malformed bytes can be recovered; new malformed or foreign-app bytes cannot be silently adopted and erased. Cleanup still requires the complete helper receipt before uninstall and artifact removal. No sibling/source data is targeted. Deletion closure now uses the compiled all-app process coordinator; other global callers are still pending.

Failing-first tests found two concrete errors: an invalid journal owner could overwrite a good checkpoint before readback rejected it, and a retry could remove a new foreign-owned profile under the same ID. Validation now precedes publication and service replay. An actual ZIP fixture also found that streamed ZIP markers can advertise size zero in their initial header; bounded decoded reads now accept valid markers and reject empty, duplicate or oversized entries. The iOS build caught a wrong initializer hidden by a test replacement; the replacement now implements the production initializer and verifies propagation of the operation context.

Actual deletion orchestration passes 335 assertions, target/phase/backup/export tests 137, and closure ordering 38. Journal syscall-failure fixtures run for both apps. Temporary real files and the shipped functions are used, with explicitly synthetic OS/service/UID boundaries. These results cover replay and ownership code, not a live Facebook installation, user-account compatibility or network/MDM acceptance.
