# App-bound backup and restore — FBLIFE-006

Facebook remains inactive. The encrypted payload now has an app-bound reconstruction path ready for a future admitted descriptor. This unit does not establish Facebook account restoration, on-device preference migration or SDK identity provenance.

Reddit retains its legacy envelope, optional app tags, seed handling and generated profile shape. An explicitly different app owner at any envelope/profile/seed level is rejected. Facebook requires an active registered descriptor, numeric schema version 2, matching explicit app tags, the registered source bundle, a complete profile object and `same-logical-identity-new-local-container-v1`. Its seed contains only the app tag: the full profile is the sole identity authority. The credential declaration must say app files included, Keychain not exported, device-bound keys not transferable, login not preserved and login verification required. Typed booleans are checked. No Facebook backup is accepted by the current inactive production registry.

The operation continues the archived logical identity under a fresh local container and derived bundle/group set. It preserves the selected app namespace and generic identity configuration, does not inherit installed clone/transaction/control metadata, and freezes the restored identity before first Open. It is not a fresh anonymous identity. Replacing a profile with a new identity remains the separate replacement operation. Same-bundle reinstall is handled by installation recovery; this cloud path does not implement it. Existing local identity uniqueness checks continue to reject a second local copy of an already reserved identity.

Proxy continuity uses the archived profile location. Clone installation, sandbox lookup and synchronization use the selected app. Sandbox lookup independently binds bundle to container instead of trusting a supplied bundle name. Worker ownership is checked after installation and synchronization and before registration. A blocked Facebook App Attest policy remains off in the worker registry. A restore failure may delete only its matching newly created candidate. A foreign or unreadable candidate is retained. A failed profile write can have committed bytes; that uncertain result now retains its prepared recovery stage and candidate instead of deleting the stage.

No app-owned files or opaque SDK identifiers are rewritten in this unit. The existing copier strips prior lease/firewall/readiness/bootstrap control files and preserves the new OS container metadata. It cannot prove that Facebook will read a preference archive under its new bundle, that family/vendor backups have the intended semantics, or that any device-bound reference remains useful. Those observations and real managed routing are required before admitting Facebook traffic. A completed file copy never proves login survived.
